# 后端升级改造任务清单：Python(evawork) → TypeScript(apps/desktop-api)

> 目标：把现有 Python 后端 `apps/desktop-py/evawork`（FastAPI，约 152 个 HTTP 端点、68 个 `.py`、约 2 万行）用 TypeScript 全量重写，收敛为单一内核。
> 新建独立进程 `apps/desktop-api`（Hono），由 `desktop-node` 主进程 spawn，监听同款端口（默认 18765），复用既有 `/api/health` 探针与 IPC 注入机制。

---

## 0. 背景与关键洞察

- **现状分层**
  - 执行层（真正跑任务）：`apps/agent-ts`（Node 服务，主进程以子进程 spawn，stdio JSON-RPC，当前为主）+ `apps/desktop-py/evawork`（Python 智能体，端口 18765）。
  - `agent-ts` 只做对话执行引擎，**不对外提供 REST**；应用全部平台 API（任务/文件/记忆/账号/模型/技能/插件/浏览器/终端…）都由 `evawork` 提供。
- **为什么能"重写不动 UI"**：前端 `apps/desktop-ui/src/api/*` 全部经 `backendURL()`（由主进程经 `evawork:backend` IPC 注入）访问后端。只要新 TS 后端提供**相同路由路径 + 相同出入参形状**，UI 几乎零改动。
- **降级策略**：逐域移植，未覆盖的 `/api/*` 暂时返回与现有 `data/mock.ts` 兼容的结构（或 501 占位由 UI 回退），保证应用全程可用、不白屏。
- **真正省空间的点**：内嵌 Python 运行时 `resources/python`（gitignored，约 27MB）随 Python 后端移除而彻底不需要（`bundle_python.py` + extraResource 删除）。Python 源码本体仅约 2MB。

---

## 1. 技术决策（已确认）

| 项 | 决策 |
|---|---|
| 位置 | 独立进程 `apps/desktop-api`，由 `main.js` spawn（与现行拉 Python 同款模式） |
| Web 框架 | **Hono**（REST/SSE/WS 均支持，依赖极小，TS 原生） |
| 端口 | 沿用 **18765**（`EVAWORK_BACKEND_PORT`），`BACKEND` 常量不变 → UI 不变 |
| 运行方式 | dev 态用 `tsx` 跑 TS 源码；打包态编译 `dist/` 并作为 extraResource 注入 |
| 契约 | 保留 `shared/agent-contract.json` 作为审批/沙箱真相源（agent-ts 与后端共用），后端加载它做 `needs_approval(mode, action)` 判定 |
| 存储 | 用 Node 侧轻量持久化（如 `better-sqlite3` 或 JSON+kv）替代 Python 侧 kv/sqlite；需评估现有 Python 存储实现再定 |
| 降级 | 未移植域返回 mock 兼容结构，避免白屏 |

## 5. 跨端耦合必保清单（重写时不可破坏）

1. **`GET /api/iam/access-token`** — TS 智能体唯一令牌来源（`tsAgent.js:79`）；返回 `{token, base_url, model, routes[], source}`（空 token=未登录，不启动 agent）。
2. **`GET /api/health`** — Electron 主进程就绪探针（`main.js` `checkHealth`/`waitForBackend`）。返回 `backend:"ts"`。
3. **`GET/POST /api/browser/commands`** — 内置浏览器命令队列（S-23），主进程 1s 轮询当心跳；`postBrowserResult` 回执路径不可断。
4. **`GET/PUT /api/settings`、`GET /api/workspace`** — 主进程/TS 子进程本机行为同步点（`syncSettingsFromBackend`、`tsAgent.fetchWorkspace`）。
5. **`shared/agent-contract.json`** — 审批/沙箱真相源，两套智能体共用；后端 `needs_approval(mode, action)` 必须按它判定，禁止另写一份。

## 6. 高风险点与缓解

| 风险 | 说明 | 缓解 |
|---|---|---|
| **IAM SSO（OAuth2+PKCE）** | 登录链路最复杂，错了全站无法登录 | Phase 1 优先、配回归测试；对照 `evawork` 的 `iam.py` 逐接口平移 |
| **任务引擎与 agent-ts 重叠** | `evawork` 的 `runner.py/agent.py` 与 `agent-ts` 双重实现 | 后端 `tasks` 仅做调度/状态/事件存储，执行委托 agent-ts（避免双重 runner/sandbox/tools） |
| **PTY WebSocket + 浏览器心跳队列** | 实时双向、与主进程强耦合 | 用 Hono WS 或 `ws` 库；保留命令队列模型 |
| **多模态 / 沙箱** | 依赖本机能力（截图、语音、命令沙箱） | 复用 `agent-ts` 已实现的 sandbox/tools；后端只做编排 |
| **存储迁移** | Python 侧 kv/sqlite 数据需在新 TS 侧可读/可建 | 优先 JSON+kv 或 `better-sqlite3`；评估现有数据格式再定，必要时写一次性迁移 |
| **出入参形状漂移** | UI 依赖特定响应结构 | 每域移植后跑 UI 端到端；保留 `data/mock` 对照 |
