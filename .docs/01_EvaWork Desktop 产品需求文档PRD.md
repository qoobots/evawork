# EvaWork Desktop · 产品需求文档（PRD）

> 本仓库是 **EvaWork Desktop**：一个桌面 AI 工作台的**客户端**。
> 技术栈：**Electron 主进程 + Vue 3 渲染层（复用界面原型）+ Python 智能体后端（FastAPI）**。
> 界面原型阶段数据来自 `apps/desktop-ui/src/data/mock.ts`；进入实现阶段后，渲染层经 `src/api/backend.ts` 直连本地 Python 后端（`http://127.0.0.1:18765`），无后端时回退 Mock。详见 `04_技术架构文档`、`05_PRD任务清单`。

## 1. 背景与目标

### 1.1 要解决的问题

桌面办公场景里，"把一件事交给 AI"的路径仍然是散的：写文档在一个工具、找模板在另一个、看使用量又要跳网页。用户需要一个**单一入口**：一句话描述要做什么，其余的（模板、插件、模型、自动化、历史产物、用量记录）都在这一个客户端里顺手可及。（2026-10-02：面向企业内部员工，不涉及订阅与权益。）

### 1.2 产品目标

1. **给出完整界面骨架**（原型阶段已完成）：把"新建任务 → 找能力（插件/技能/模板/设计系统）→ 定时化（自动化）→ 在通讯工具里收结果（办公助理）→ 回看产物（我的文件）→ 管账号（管理账户/设置）"这条主链路的界面全部铺出来。
2. **交互可点、状态可见**：搜索、分类、收藏、开关、弹层这些控件必须真的有反应；没有后端支撑的按钮，宁可做成静态或明确禁用，也不允许"点了像没发生"。
3. **可作为后续实现的施工图**（实现阶段进行中）：每个页面接什么数据、有哪些状态（空态/加载/列表/详情/开关），由 `05_PRD任务清单` 拆解成可排期、可验收的任务。

### 1.3 非目标与阶段划分

产品分两阶段交付：

- **原型阶段（已完成，v0.1.0）**：无后端、纯 Mock、壳只开窗。明确了"界面长什么样"。
- **实现阶段（进行中，v0.2.0+）**：技术栈定为 Electron + Python，目标是把原型接成真实可用的客户端。该阶段**会接本地后端、会做真实执行与持久化**；具体任务见 `05_PRD任务清单`。

实现阶段仍明确**暂不做**（避免范围蔓延）：

- 多设备云同步、跨端账号体系（先做本地会话，T-042）。
- 真实计费与支付。**（2026-10-02 更新）** 产品面向企业内部员工，因此**不只"不做支付"，而是整个商业化口径都不存在**：无套餐档位、无积分余额、无订阅与发票页面，"升级权益"入口已下线；只保留**使用量记录**（任务数/产物数/趋势/估算 token，T-041）。
- 完整 i18n 与暗色主题（先做令牌化铺垫，T-051/T-052）。

## 2. 用户与场景

| 角色 | 典型诉求 | 对应界面 |
|---|---|---|
| 通用办公用户 | 一句话交代一件日常任务（整理纪要、做 PPT、分析表格） | 新建任务（`/`） |
| 想扩展能力的用户 | 找现成插件/技能，按分类挑 | 插件市场（`/market`） |
| 想要成稿起点的用户 | 直接套模板 | 模板库（`/templates`） |
| 做界面/物料的用户 | 定风格、看色板与组件规范 | 设计系统（`/design`、`/design/:id`） |
| 想让它定时跑的用户 | 配周期性任务 | 自动化（`/automation`） |
| 在 IM 里办公的用户 | 绑定飞书/微信，@ 一下就开工 | 办公助理（`/office`） |
| 回头找产物的用户 | 按类型翻自己做过什么 | 我的文件（`/files`） |
| 关心使用量的用户（企业内部） | 看用量（任务数/产物数/估算 token/趋势）、规则与集成 | 管理账户（`/admin/*`）、设置浮层 |

## 5. 功能需求

状态标记：**已实现（Mock）** = 界面与交互都可用，数据是 Mock；**静态** = 界面存在但点击无副作用（不假装能用）；**未实现** = 本阶段没有。后端接入与真实化任务见 `05_PRD任务清单`。

### FR-1 全局壳　已实现（Mock）
- 侧栏固定 186px：左上角 EvaWork 品牌区 → 7 个导航 → 任务列表 → 我的菜单。
- 原 Work / Code / Design 三档切换已于 T-142 移除，产品收敛为单一 EvaWork；首页恒为 Work 呈现，输入框文案/推荐卡不再随模式变化。
- 路由以 hash 模式承载，主壳与管理账户按路由前缀切换（`App.vue`）。

### FR-2 新建任务　已实现（Mock）
- 输入框回车或点发送 → 在侧栏任务列表顶部新增一条任务；空输入时发送按钮禁用。
- 输入区底部工具条：`+` 菜单（8 项，**静态**）、审批模式选择（三档，**已实现**）、模型选择（内置 6 个，**已实现**）、语音按钮（**静态**）。
- 快捷 chips 与推荐卡随模式变化（Work：4 条建议；Design：3 张建议卡）。
- 实现阶段：发送后走真实任务状态机并流式回填（T-020/T-021）。

### FR-3 插件市场　已实现（Mock）
- 插件 / 技能双 Tab；插件侧支持分类（11 类）+ 关键词搜索（按名称与描述匹配）；技能侧支持分类（6 类）。
- 顶部三张能力专题卡。**"管理"按钮、技能"上传技能"按钮为静态**。
- 实现阶段：列表/搜索来自后端，安装/启用真实生效（T-011/T-030）。

### FR-4 模板库　已实现（Mock）
- 精选 / 收藏双 Tab；分类（10 类）+ 关键词搜索 + 收藏星标，三者可叠加过滤，空结果有空态文案。
- 卡片封面为 CSS 渐变 + 几何装饰（bars / radar / chart / kpi / site / photo / doc 七种），无位图。
- 实现阶段：收藏落盘（T-012）、详情页与应用生成产物（T-032）。

### FR-5 设计系统　已实现（Mock → 后端示例）
- 列表页：8 套内置（EvaWork、TraeCode、Volcengine、TikTok、Doubao、Apple、Claude、Google）+ 自定义空态。
- 详情页四个 Tab：主题（色板/功能令牌/字体）、组件、图形（60 个图标名，支持搜索）、设计规范（含手机暗色 mock）。
- 实现阶段：**已示例性接入后端真实色板**（T-010）；"创建副本"/自定义待做（T-033）。

### FR-6 自动化　已实现（Mock）
- 三个 Tab：已配置（2 条，带开关，可切换）、执行历史（空态）、任务模板（8 张）。
- 顶部"手动新建 / 在对话中创建"为**静态**。
- 实现阶段：CRUD + 调度落盘（T-013）。

### FR-7 办公助理　已实现（Mock）
- Hero 横幅 + 通讯工具清单：飞书、微信可"去绑定"（**静态**），企业微信、钉钉标"即将上线"。
- 实现阶段：绑定流程（T-034）。

### FR-8 我的文件　部分
- 三个来源 Tab（本地/云端/飞书）、类型筛选（7 类）、视图切换图标均为界面状态；**列表本身是空态**，搜索与筛选尚未接到列表（因为列表为空）。
- 实现阶段：本地目录真实扫描（T-014/T-035）。

### FR-9 管理账户（深色控制台）　已实现（Mock）
- 用量管理：任务数/产物数、估算 token、任务量趋势、用量明细表，时间范围可切（1/7/30 天）。（2026-10-02：总积分、通用/Work 专属拆分、奖励积分随计费口径下线。）
- 账号设置：头像、昵称、5 项账号操作、隐私模式开关（静态）。
- ~~订阅管理：当前方案（免费）+ 购买记录空表~~。**（2026-10-02 下线）** 企业内部员工使用，不计费。
- 仪表盘：53×7 活跃热力图（确定性种子）、代码规模/对话次数、最佳拍档与模型偏好。
- 收藏盒：空态。
- 规则：可新建/取消的规则编辑器（保存为静态）。
- 命令：内置 3 条 + 可新增/删除（仅内存）。
- 外部应用授权：6 个应用，开关可切换（仅内存）。
- 云端运行环境：8 个运行时版本 + 3 条资源配额条。
- MCP：6 个 Server，支持关键词搜索。
- 实现阶段：规则/命令/授权/MCP 落盘（T-015/T-040）。

### FR-10 设置浮层　已实现（Mock，17 节）
账号、用量管理、通用、TRAE 移动端、权限审批、MCP、模型、对话流、外部应用授权、浏览器、电脑控制、云端运行环境、工作树、命令、规则与记忆、Beta、关于 EvaWork。**内容按设计稿铺满，除左栏切换与少量开关外不持久化**（实现阶段 T-040）。

### FR-11 消息　已实现（Mock）
- 消息：3 条静态消息，侧栏"我的 → 消息"带未读 3。
- ~~升级权益：4 档套餐（Lite / Pro / Pro+ / Ultra）、连续包月与单月切换、二维码占位、同意协议勾选~~。**（2026-10-02 下线）** 企业内部员工使用，不计费、无权益档位，界面不再提供该浮层。

### FR-12 基础体验　部分

## 6. 非功能需求

| 项 | 约定 |
|---|---|
| 外部资源 | **零外部图片**：所有图标为内联 SVG（62 个键，见 `components/icons.ts`），插画/二维码/热力图/色板用 CSS 渐变与几何块 |
| 主题 | 主壳亮色（令牌在 `styles/app.css` 的 `:root`）；管理账户为独立深色控制台 |
| 字体 | `'Segoe UI'`、`Microsoft YaHei`、system-ui 回退，不加载网络字体 |
| 打包 | electron-builder 出 MSI/NSIS（Windows）/ dmg；Electron 直接加载本地 dist，无 `custom-protocol` 概念 |
| 构建 | `pnpm build`（vite）→ `apps/desktop-node` 用 electron-builder 打包；前端产物 158KB JS + 18KB CSS（gzip 后约 62KB / 4KB） |
| 权限 | 渲染层 `contextIsolation: true` + `nodeIntegration: false`；后端仅监听 `127.0.0.1`、开发期放开 CORS，发布期收紧；模型 API Key 仅走环境变量 |
| 后端契约 | 渲染层经 `src/api/backend.ts` 直连 `http://127.0.0.1:18765`；无后端时回退 Mock，界面不崩 |

## 7. 验收清单（实现阶段）

1. `pnpm typecheck` 无错误、`pnpm build` 成功。
2. `npm start`（electron）能启动窗口并拉起 Python 后端，启动后进程存活、渲染层拿到后端地址（此前原型阶段重复建窗会崩溃，现已改为壳只开窗）。
3. 所有 18 个 hash 路由都能渲染出内容，控制台无 `console.error` / `pageerror`。
4. 搜索框、分类、收藏、开关这类"看得见的控件"必须有实际反应；没有后端的按钮保持静态且不与已实现项混淆。
5. 文档与实现一致：改界面/后端后同步 `03_UI设计文档` 与 `05_PRD任务清单`。

## 8. 风险与开放问题

- **Mock 与真实能力的落差**：界面铺得很满，接后端时几乎每个页面都要补加载/错误/重试状态，当前完全没有这些状态（T-050）。
- **主壳只有亮色**：管理与设置若要做暗色，需要把设计令牌抽成主题变量，现在是两套硬编码色值（T-051）。
- **任务模型未定义**：现在"任务"只是侧栏一条标题，没有详情页、没有状态机、没有产物（T-020）。
- **用量口径**：任务数/产物数/趋势为真实统计，token 为估算（字符数/4）并显式标注；~~积分/订阅~~已下线，界面不再出现额度与升级入口（T-041）。
- **后端耦合面**：渲染层经 `src/api/backend.ts` 直连本地 Python 后端；后端未起时必须有 mock 兜底，否则界面白屏/报错（已在设计中处理）。
- **开放问题**：自动化是否要支持手动新建（当前静态）？我的文件是否先接本地目录？办公助理的绑定流程是否走 OAuth？
