# GeneralSkill · EvaWork 每段对话必带的通用 Skill 选型

> 目标：从本地 54 个 Skill（`apps/skills`）中挑选**常用且通用**的 Skill，作为 EvaWork 智能体每段对话默认注册携带的技能集；本地缺失的通用能力自行补撰。
>
> 选型依据：`.docs/13~18`（Claude Code 对话解剖与技能编排分析）、DSH 智能体源码（`D:/05workspaces/deepseek-harness`）、codex 智能体源码（`D:/05workspaces/codex`）、GitHub 社区主流 Skill 框架（obra/superpowers、anthropics/skills、mattpocock/skills 等，2026 年最活跃的 Agent Skills 生态）。

---

## 1. 选型标准

一个 Skill 要进入"每对话必带"集合，须同时满足：

1. **通用性**：与具体技术栈 / 领域无关，任何项目、任何任务类型都用得上；
2. **高频性**：对应 Claude Code、DSH、codex 三家**都常驻强调**的行为，或对应绝大多数对话的必经阶段；
3. **行为修正性**：修正的是模型的高频失败模式（瞎编、假完成、表面补丁、先改后读），而不是传授冷知识。

**不入选的典型**：领域专精类（animation 系列、ask-sonner、apple-design、mobile-native、frontend-design、data-analysis 等）——常用但不通用，应按需触发；meta 类（writing-skills、diagnosing-superpowers）——低频；办公场景类（meeting-notes、internal-comms、email-draft、retro 等）——按用户角色选配，不宜全局常驻。

## 4. 自撰的 2 个 Skill 说明

本地 54 个 Skill 在 DSH / codex 收敛出的两个"必带"能力上有缺口，故补撰：

- **`codebase-exploration`**：DSH 把"专用工具优先、先读后改、offset/limit 续读"写进每工具常驻提示；codex 同样强调。本地 Skill 里没有对应物（`wayfinder` 只管超大工作量）。
- **`task-persistence`**：codex 的 "Autonomy and Persistence"（不解不停、不许瞎编、根因优先）与 DSH 的 goal blocked 判据（连续 3 轮 + 具体原因 + "难度/不确定不算 blocked"）都在系统提示词层常驻；本地 Skill 无对应物。

## 5. 落地建议

1. **常驻注册，按需加载**：对齐 `.docs/16` 的结论——技能清单是运行时注入的数据，不是提示词常量。15 个 Skill 只以"名称 + 一句话描述"常驻上下文（渐进披露），正文在命中触发条件时才加载，单对话 token 增量可控。
2. **入口路由唯一**：`using-superpowers` 作为默认第一技能，由它判断本轮该唤起哪些后续技能，避免多技能互相拦截（社区实践中多框架混装的常见事故）。
3. **条件性技能**：`test-driven-development` 仅当仓库已有测试体系时强制；`dispatching-parallel-agents` 仅当智能体具备子代理能力时注册。
4. **描述即触发器**：每个 Skill 的 `description` 要写成"用户说 X / 模型即将做 Y 时用它"（参照 `.docs/16` 中 dataviz 的写法），这是触发命中率的决定因素。
