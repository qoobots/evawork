# 总结

## 先问清：总结给谁看、用来干什么

同一份内容，给同事看和给自己看，该保留的东西完全不同：

- **给自己看**（做决策）→ 保留结论、风险、待办，过程可省
- **给同事看**（对齐）→ 保留背景与影响面，省掉推理过程
- **存档**（以后查）→ 保留结构与关键词，细节可省

不确定就按「结论 + 风险 + 待办」这三段来，最不容易出错。

## 压缩的优先级

按这个顺序丢东西，先丢后面的：

1. 重复的内容（同一件事说了三遍，合并成一句）
2. 过程细节（尝试了什么、为什么失败）→ 只在**失败原因对结论有影响**时保留
3. 例子与推导 → 只留最能说明问题的那一个
4. 修饰词与铺垫

**不要丢**：结论、数字、明确的待办、风险与影响范围。

## 输出结构（按内容类型选）

- **日志/运行结果** → 发生了什么 · 真正的错误 · 影响范围 · 建议动作
- **代码/技术文档** → 它做什么 · 关键约定 · 我要注意的地方
- **会议/聊天** → 结论 · 待办（谁、什么时候）· 未决问题
- **长文/资料** → 核心观点 · 支撑依据 · 与我要做的事的关系

## 纪律

- **数字要准**：「3 处失败」不能写成「若干处」。原文有的数字一律照抄
- **不确定就标出来**：「这里没写清楚是否包含 X」，比猜一个结论有用
- 长度由内容决定：本来就短的，别硬凑长
