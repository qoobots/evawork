# 会议纪要

## 纪要的唯一检验标准

**读完它，不 attending 的人能不能知道自己该做什么？**
做不到就说明纪要没写好——不是写少了，而是没写「谁、做什么、什么时候」。

## 采录方式

不要凭记忆写。按这个顺序取材：

1. 有原始记录（会议记录、聊天、日志）就先读它——**别靠转述**
2. 没有记录时，用 todo_write 把待办先落下来，**宁可先记后补**，不要凭印象写结论
3. 分清「说了什么」与「决定了什么」：讨论过程不是决议，猜测不是决议

## 模板

    ## 主题
    时间 / 参与人
    
    ### 结论
    - （逐条，可执行）
    
    ### 待办
    | 事项 | 负责人 | 期限 |
    |---|---|---|
    | | | |
    
    ### 未决
    | 问题 | 谁来定 | 什么时候定 |
    |---|---|---|

## 三条硬规矩

1. **待办必须有负责人和期限**。「大家跟进一下」不是待办，是没写完的会议记录
2. **未决事项写清谁来定**。悬着的决策会一直悬着
3. **不写「一致同意」这种没有信息量的词**。要么写清结论，要么老实写「未达成一致」

## 交付时

写完单独把**待办列表**摘出来给用户——多数人只关心自己那一行。

工具名以当前可用清单为准（read_file / list_dir / grep / write_file / patch / run_command / todo_write / delegate / load_skill）。
