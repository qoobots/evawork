# 排查技能系统

## 概述

有时候问题不在某个任务里，而在**"技能这套东西没起作用"**：
该用技能时没触发、触发了但被无视、按部就班却做错、同一件事反复做。

这时候要排查的是**技能系统本身**，不是当前任务。

**核心原则：先确认技能有没有真的进入上下文、进入之后有没有真的被读。**

## 先分清是哪一类问题

| 症状 | 大概率原因 | 该看哪一节 |
|---|---|---|
| 技能**从没被列出** | 发现机制坏了（目录／格式／环境变量） | A：技能有没有被发现 |
| 列出来了但**没被读** | 触发词不匹配、或模型不知道该读 | B：触发条件 |
| 读了但**没被执行** | 技能正文太弱、口吻不对 | C：技能内容 |
| 执行了但**结果不好** | 技能与项目实际不符、缺项目特定内容 | D：适配 |
| **同一件事反复做** | 流程里缺"检查"环节 | E：流程 |
| **无视计划** | 计划被截断、或计划本身不可执行 | F：计划质量 |

## A：技能有没有被发现

1. 可用技能列在系统提示的 `skills` 一节——先确认它**真的在那里面**
2. 一个都没有 → 检查目录：用户级 `~/.evawork/skills/`（或 `EVAWORK_SKILL_DIR`）
   与项目级 `<工作区>/.evawork/skills/`；每个技能目录下必须有 `SKILL.md`
3. 有目录但读不到 → 检查文件名、编码、BOM
4. 内置技能没出现 → 检查数据目录里有没有落盘副本（内置技能是启动时补进去的）

## B：触发条件

技能列出来了却没被读，通常是**描述写得不够像"触发条件"**。

- description 写的是**它是干什么的**，而不是**什么时候该用它**
- 触发词太抽象（"提升代码质量"这种没人会搜）
- 触发词用了用户在中文场景根本不会说的词

**修法**：description 改成「**用户说 X／Y／Z 时用它**」这种具体说法。

## C：技能内容

读了但没被执行：

- 正文全是"应该"和"要"，**没有可执行的动作**
- 规则抽象、没有具体判据（"代码要清晰"这种没法执行）
- **太长**——重点被淹没，模型读了就忘
- 语气是"建议"而不是"步骤"

**修法**：改成检查清单／编号步骤；每条都要能回答"怎么算做到了"。

⚠️ 另一个常见原因：**技能里引用的文件不存在**（比如指向 `references/x.md` 但没拷进来），
模型读完发现找不到，后面的步骤就放弃了。

## D：与项目实际不符

技能执行了但结果不好，通常是**通用方法论撞上了项目 specifics**：

- 项目用 pnpm，技能里写的是 npm
- 项目的目录结构与技能里的例子不同
- 项目有自己的约定（设计系统、错误码规范）

**修法**：在技能里**点名本项目的实际工具与路径**，别让它去猜。
"用 `run_command` 跑 `pnpm test`"比"跑测试"有用得多。

## E：流程缺检查环节

反复做同一件事，通常是流程里**少了一环**：

- 改了代码**没重跑验证** → 缺"完成前先验证"
- 反复重构同一处 → 缺系统化调试（没找根因就在乱试）
- 计划写着写着跑偏 → 缺头脑风暴（意图没对齐）

**修法**：在流程里显式加"检查点"，而不是靠模型自觉。

## F：计划质量

无视计划，按计划本身的问题查：

- 步骤**不可验证**（"改进性能"这种）
- 步骤太大（一次做完十几个文件）
- 缺**确切路径**（"改一下配置"）
- 缺**接口签名**（子代理猜不到邻居用什么名字）

## 硬规则

1. **先确认技能真的进了上下文**——别凭印象判断"我应该用了"
2. **区分"没触发"和"触发了但没用"**——两者的修法完全不同
3. **一次只改一处**（一次改多个技能，然后无法归因是谁起的作用）
4. **修完要验证**：让同类任务再跑一遍，看行为是否变
5. **如实说"没找到原因"**——比编一个解释有用

## 红旗

| 想法 | 事实 |
|---|---|
| "这个技能没用，删了" | 先查清是**没触发**还是**内容弱**——前者改描述，后者改内容，删是最差解 |
| "我明明让它用了" | 你"让它用"和它"自己判断该用"是两件事，看触发词 |
| "重写一遍就好了" | 重写解决不了触发问题，还会丢掉有价值的内容 |
| "改三个技能一起试" | 一次改一个，否则不知道是谁起的作用 |
| "这个技能模型就是不听" | 大概率是语气／长度／可执行性问题，不是"模型不听话" |

## 排查清单

- [ ] 技能出现在可用清单里吗？（A）
- [ ] description 里有具体的触发说法吗？（B）
- [ ] 正文有可执行的动作与判据吗？（C）
- [ ] 引用的文件都在吗？（C）
- [ ] 技能里的命令／路径符合本项目实际吗？（D）
- [ ] 流程里有明确的检查点吗？（E）
- [ ] 计划的步骤可验证、路径确切吗？（F）
- [ ] 修完：同类任务重跑验证了吗？
