# 排障

## 先复现，再猜测

**不能复现的 bug 只能猜**。所以第一步永远是：

1. 拿到确切的报错文本（完整，不要截断）
2. 拿到触发条件（做了什么操作 / 什么输入）
3. 跑一遍确认能复现

复现不了就直接说「我无法复现，需要更多信息」，不要直接开始改代码——那样改的是运气。

## 定位：从报错往回追

1. **读完整报错**，包括堆栈的**最底层**（最底下那行才是真凶，上层只是调用链）
2. **区分症状与病因**：空指针只是症状，病因是那个没判空的逻辑
3. **二分法**：怀疑范围太大时，从中间切一刀验证，比逐行读快得多
4. **先加日志/断点验证猜想**，再改——不要凭直觉改完就宣布修好了

## 改完必须验证

- 原来的复现路径再跑一遍，**确认好了**
- 顺手测一个相邻场景（同类输入、边界值），看有没有连带问题
- 说清改了什么、为什么那处是病因

## 报告格式

    现象：什么输入 → 什么报错
    病因：哪一处、为什么
    改法：改了什么
    验证：怎么确认好了（实测结果，不是「应该好了」）

## 不要做的事

- 试一个改动看看能不能跑——过了不代表对，可能只是掩盖了症状
- 同时改好几处（无法判断哪一处起了作用，也无法回滚）
- 删掉报错信息、吞掉异常让它不报——那是把问题藏起来
