# 内部沟通

## 铁律：结论先行

读者的耐心有限，且**往往只读第一段**。所以：

- 第一句就给结论或请求，不要铺垫背景
- 背景放第二段，别放开头
- 需要对方做决定的事写在最前面，并说清**不做会怎样**

## 三种常见文体

**周报／月报**：做了什么（结果，不是过程）→ 遇到的问题 → 下一步。
过程写多了会淹没结果；「推动了 X 的落地」不如「X 已上线，指标从 A 变成 B」。

**公告**：一句话说清「发生了什么 + 谁要做什么 + 什么时候」，并写明影响面（谁受影响、谁不用管）。

**评审纪要**：结论 → 决议（逐条、可执行）→ 待定项（写清谁来定、什么时候定）。
**待定必须有主人和期限**，否则纪要等于没写。

## 常见毛病

- 用工作量代替成果（「完成了 3 个模块」→「这 3 个模块让 X 从 2 天变成 5 分钟」）
- 把风险藏在末尾（风险要单列，并写清谁来跟）
- 形容词代替数字（「效率明显提升」→「X 从 20 分钟降到 3 分钟」）
- 罗列流水账（读者要的是结论与决策，不是工时）

## 语气

- 对上：给结论、给选项、给建议，别只抛问题
- 对下：说清做什么、为什么、做到什么算完成
- 对平级：先说约束，再要支持
